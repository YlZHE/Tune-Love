# 当前播放器调式识别与标题栏显示

日期：2026-09-29。

用户已在对话中确认本轮方向：复用 libkeyfinder，分析当前播放器的真实音频；首版为 12 个主音 × 大调／小调；未识别时保留左上角标题，识别稳定后显示调式，沿用歌名切换动效并适度加大、加粗字体。GPLv3-or-later 依赖选择已获同意。本文件供实施前审阅，不代表功能已实现或准确率已经验收。

## 范围和不变约束

- 仅修改 `now-playing` 应用。保留原音频采集、播放控制、三个旋钮、去人声预览、配色、背景、动画、窗口尺寸和设置页面。
- 只分析现有已确认播放器进程树的音频。不开麦克风，不采集系统混音，不增加虚拟声卡或播放器注入。
- 识别的是歌曲调性，不是歌唱者的逐音符音高。首版不宣称识别多利亚等全部教会调式，也不宣称能正确识别任何歌曲。
- 不向 Auto-Tune 提交 Key／Scale，不改变既定的卡卡兼容接入路线。本阶段产物不是卡卡内部识别流程的复现声明。
- 音频不上传、不保存为录音。原始 PCM 仍留在有上限的后台内存，不经 WebView IPC。
- 只构建调试版，不更新正式版或安装包。不初始化 Git；当前目录没有 Git 仓库，不创建提交或 worktree。

## 识别引擎与构建

使用 Mixxx 维护的 libkeyfinder；基线固定为 v2.2.6，对应提交 `a409c7447e9f440a12627ff4a540a43e41b48a55`，不跟随浮动分支。它提供原始音频到调性估计的算法，实现者不得以自行拼装的 FFT 最大峰检测替代。

优先复用已有 `libkeyfinder-sys` 绑定。当前绑定的构建脚本通过 pkg-config 查找系统库；如果不适用于本项目的 Windows MSVC 自包含构建，仅补一个薄的构建／FFI 适配层，继续调用原版 libkeyfinder，不另写识别算法。FFTW 作为上游依赖一同固定版本、核对来源和许可；原始源码及许可保留出处，改动单独记录。

发布材料须标明 libkeyfinder 和 FFTW 的许可、版本及源码来源。对话中接受该依赖不等于已经完成整个仓库的发布许可审计；商业 DLL、逆向取证材料、个人歌曲和测试录音仍不得混入发布目录。

## 数据流与后台隔离

沿用 `AudioState::analysis_window()` 的当前播放器 48 kHz、双声道 f32 PCM。分析所需的输入整理和电平归一化只处理工作副本，不能改变可视化频段或原采集数据。

新增独立后台分析工作者，最多同时运行一个分析任务；不在捕获回调、WebView 线程或媒体元数据工作者中运行识别。初始分析调度间隔为 1 秒，完成后再安排下一轮，慢任务不堆积。以最多 8 秒的新鲜音频窗为基础，至少积累 6 秒有效输入才尝试发布候选；这些是首版调度参数，不是对识别延迟或准确率的承诺。

读取 PCM 时一并取得：来源 ID、歌曲标识、媒体目标代次、采集代次、样本结束序号。一次分析只在复制数据时短暂持有采集锁，计算期间释放锁。相同结束序号不重复计入稳定投票。

断续、重连、过期、来源切换和歌曲切换会清除待分析历史，并使对应代次改变。计算结束后再核对目标和采集代次；旧任务即使完成，也不能给新歌曲发布结果。媒体代次还用于拦截已观察到的 A→B→A 切换。

## 结果稳定与有效性

- 无有效音频、静音、非有限样本、输入不足或库返回 SILENCE 时不发布调式。
- 非静音输入在分析副本中归一化，避免只因播放器音量较低就失去分析能力；极低噪声不能无限放大。阈值通过有标注的测试信号检查，并在验收报告中记录。
- 初次显示要求连续 3 次带有新样本的有效分析得到同一候选。稳定次数是防抖策略，不是统计学置信度，不向用户显示伪造的准确率百分比。
- 已显示的结果不会因一次短暂的不同候选跳变；更新为另一结果要求连续 5 次有效的新分析一致。静音或短暂证据不足不凭空制造新结果。
- 单一音高、打击乐和无调性噪声必须作为负向用例。若实际引擎无法可靠区分某种输入，报告限制，不以演示结果冒充已解决。
- 暂停同一歌曲时停止分析、清理 PCM，保留已确认显示结果；恢复后仅用新音频继续分析。切歌、换来源或媒体目标失效立即清除显示结果。

## 前后端契约

新增只读 `get_key_detection` 命令，传递结果和归属，不传 PCM。结果包含：

```ts
type KeyDetection = {
  sourceId: string | null;
  trackKey: string | null;
  targetGeneration: number;
  status: "idle" | "analyzing" | "detected" | "unavailable";
  key: { pitchClass: number; mode: "major" | "minor" } | null;
  updatedAtMs: number;
};
```

`pitchClass` 采用 C=0、C♯=1、…、B=11。上游枚举值在适配层显式转换，不直接作为 Auto-Tune 参数值。前端只接受合法音名、合法模式及与当前媒体来源／歌曲／代次匹配的结果；坏值和迟到值回退为标题。

前端低频读取此快照，不复用约 60 Hz 的音频动画轮询。窗口隐藏时不继续前端读取；后台分析仍按既定节奏进行。返回窗口后重新核对当前媒体和识别结果。

## 标题栏视觉

- 未识别、等待稳定、无可用媒体或分析失败：左上角显示 `AutoTune Helper`，不新增百分比、进度提示或诊断标签。
- 有有效稳定结果：显示 `A 小调`、`C♯ 大调` 等短标签。音名采用一致的升号记法，模式显示“大调”或“小调”。
- 保留现有音乐图标、右侧置顶／设置／关闭按钮、标题栏高度和拖动区域。
- 调式文字采用约 14 px、650 字重；实际以原生小窗不裁切、不挤压右侧按钮为验收依据。
- 复用歌名现有 Motion 动效配置：旧文字向上淡出，新文字从下方进入，旧文字先退出可视区；不重新设计一套近似动画。减少动态效果时沿用现有淡入淡出回退。
- 相同结果轮询不得反复触发动画；识别结果更新、结果清除及标题恢复才触发切换。

## 验收

1. 原版引擎集成：使用有标注的合成和弦／终止式样例检查大小调及主音映射；覆盖全部 24 个标签，不将标签映射通过等同于真实音乐准确率通过。
2. 输入有效性：静音、低电平、非有限输入、单音、噪声、打击乐型测试；已知调性样例整体降音量后不应仅因电平改变结果。记录实际无法满足的限制。
3. 状态机：新样本投票、相同窗不重复投票、初次稳定、结果更新防抖、暂停保留、切歌清理、重连清理、A→B→A 和后台迟到结果拒绝。
4. 界面：标题回退、调式标签、字号字重、同结果不重播动效、与歌名同样的切换轨迹、减少动态效果、拖动区域和右侧按钮不受影响。
5. 回归：现有 Rust、前端单元和浏览器测试；原生只读验收脚本的 IPC 白名单加入新的读取命令，不放宽实际写入权限。
6. 实测：在用户当前播放器上检查真实 PCM→识别结果→标题栏的完整链路，记录采样时长、分析耗时及内存有界性。不通过切换歌曲名或构造前端 fixture 代替真实识别。不为本任务擅自更改播放器队列或操作宿主。
7. 对真实歌曲，仅在有可信调性标注或明确对照时声称识别正确；读到了调式只证明链路运行，不证明音乐学结论。未经测量不承诺固定秒数或总体准确率。

## 已知边界

当前采集隔离是播放器进程树级，不等于从同一进程里分离歌曲、提示音或不同浏览器标签页。识别整段混音可能受人声、强鼓点、关系大小调、转调和无调性素材影响。该版本不能据此宣称达到 Auto-Key 或卡卡的完整准确率与兼容性。
